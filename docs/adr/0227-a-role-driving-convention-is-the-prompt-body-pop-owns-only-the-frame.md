# A role-driving convention is the prompt body; pop owns only the frame

[ADR-0226](0226-a-convention-always-answers-and-a-recipe-is-never-a-rank.md) makes a **Convention kind** always answer with rules to follow. That raises the question of how much of an agent's prompt those rules are allowed to be — and pop's two judging roles answer it differently today by accident rather than by design. The `commits` convention reaches the **Verifier** as one labelled section inside a prompt pop wrote end to end. The `code-review` convention reaches the **Reviewer** the same way, even though it is the whole substance of that agent's job.

Neither role's *mandate* is pop's opinion. What good code looks like, and what it takes to believe work is sound, are the team's and the human's. What is unavoidably pop's is the reply it parses: a malformed Verifier response resolves to NEEDS-HUMAN, so a well-meaning rewrite of the whole prompt would park every set at VERIFY-FAILED.

The decision, in four parts:

1. **A kind declares its consumption shape, and pop honours it at every call site.** A *role-driving* kind — `verification`, `code-review` — is an agent's entire mandate, so the convention is the prompt **body** and pop supplies only a frame around it. A *step-informing* kind — `commits`, `issue-tracker` — is a fact a prompt about something else needs, so it stays a labelled block inside pop's own prompt. Recording this as a property of the kind rather than a habit of each call site is what tells the author of the next kind that they owe it a decision.

2. **The frame is two things, not one.** A **Role preamble** precedes the body: who the agent is, what it may touch, its posture. A **Response contract** follows it: the reply format pop parses and what a malformed reply resolves to. They are named separately because they share nothing but authorship, and a container noun would only ever be defined as "these two unrelated things". Neither is overridable — pop needs both to work — and neither is a **Convention overlay**, which is entirely the human's; reusing that word for pop's non-negotiable wrapper would make it mean two opposite things.

3. **Envelope over block for the role-driving kinds, because one voice beats two.** The rejected alternative kept pop's prompt as the frame and had the convention *supplement* it. That leaves pop still saying what to check while the team's document also says what to check, so a team's answer argues with pop's, and there is no rule for which wins. With the convention as the body there is exactly one voice on what to check, and pop's non-negotiables shrink to the two things that are genuinely structural rather than opinions about verification.

4. **`verification` becomes the fourth kind, and its Shipped convention is today's prompt body.** The kind answers how work is checked here — the build and test invocation, what is a whole-tree gate versus a scoped one, what evidence counts as having run it — which is a fact about a repository that no pop surface holds and that every pop-spawned agent currently rediscovers, reaching it only when an agent CLI happens to auto-load `AGENTS.md`. Today's `verifier.tmpl.md` middle becomes the Shipped convention; the acceptance-criteria-are-authoritative sentence and the done-AFK scope rule stay in the frame, being pop's machinery rather than a standard. The name collides with nine existing glossary terms under "verification", and coherently: the kind is literally the standard **Agent verification** follows, so the shared word tells the truth where a new word for the same referent would not.

## Consequences

- The `code-review` Shipped convention is Matt Pocock's two-axis Standards-and-Spec review. This knowingly duplicates spec judgment: the Reviewer will weigh it from the changed files while the Verifier weighs it from the acceptance checkboxes, and nothing reconciles them. It cannot produce a conflicting *gate*, because **Code review** reaches no verdict by design (ADR-0214) and its whole output is an advisory **Review artifact** — so the worst case is a human reading a spec complaint beside a PASS, which is a second opinion rather than a defect. The `reviewer.tmpl.md` sentence forbidding the Reviewer to check acceptance criteria therefore goes.
- The `code-review` recipe's smell baseline stops being a floor beneath a method and becomes part of the Shipped convention's Standards content — reachable by the consumer that needed it, which under ADR-0226 it no longer would have been.
- `reviewer.tmpl.md`'s dead "No code-review convention is recorded" arm is deleted rather than revived: after ADR-0226 the condition cannot arise.
- The implementer prompt is a candidate consumer of the `verification` convention for later — an agent that must check its own work before printing `TASK_COMPLETE` needs the same fact — but this ADR wires only the Verifier.
