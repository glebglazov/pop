# Routine intent lives in prompt frontmatter, and the manifest slims to machine state

Project routines ([ADR-0138](0138-project-routines-are-committed-prompts-discovered-live-from-pop-routines.md)) express per-routine settings as YAML frontmatter on the prompt file, which would have left authored Routines on a second format (`manifest.json`). Rather than carry two intent formats, the manifest is split by **ownership**: authored intent — the optional schedule, the runtime agent list, and effort — moves into frontmatter at the top of the authored Routine's `prompt.md`, the same shape a Project routine uses; machine state — the pause bit with reason and created-at — stays in a slim JSON sidecar, renamed `state.json` (the bound directory rides there too, as a registry fact rather than intent).

The split line is deliberate: intent is human-authored and run-affecting, so it belongs in the file humans and refinement agents already edit; pause state is machine-mutated (the daemon flips it on failure and drift, ADR-0128), and machine-rewriting a human-edited file invites edit races — in the project-routine case it would even mean pop rewriting a committed repo file at runtime. One intent format everywhere means agent refinement edits one file, and copying a routine between project and authored worlds is a file copy.

Boundary rules: the Run-affecting fingerprint splits the file — frontmatter counts as settings, the body as prompt — preserving the ADR-0128 distinction. The validated write paths (`pop routine edit --schedule/--agent/--effort`, the dashboard modals) remain the mandated route for agents and now rewrite frontmatter, so the schedule parser is never bypassed on the write side; on the read side, invalid frontmatter (unparseable YAML, or a schedule the parser rejects) suspends only that Routine with a warning, exactly the corrupt-manifest discipline — never silently treated as unscheduled, never fatal to the registry.

Migration is a hard cut performed once on this machine: routines are a dev preview with no other users, so no back-compat reader for intent in `manifest.json` is kept.
