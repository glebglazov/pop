# Repo setup ships as setup-matt-pocock-skills, an overlay kept under its upstream name

Repositories need preparing for the Task planning skills: the `docs/agents/issue-tracker.md` doc that is layer 1 of Work-store resolution ([ADR-0136](0136-planning-skills-publish-through-a-work-store-seam.md)), the domain-docs layout (CONTEXT.md, `docs/adr/`, `docs/agents/domain.md`), and an Agent-skills block in CLAUDE.md/AGENTS.md. A Go command (`pop integrate repo`) was considered and rejected: the task is judgment-laden (tracker choice, editing existing prose, monorepo layout), `integrate` is glossary-reserved for agent-side wiring, and no pop Go code writes into a repo tree today — a skill keeps that boundary intact.

Instead, Matt Pocock's `setup-matt-pocock-skills` ships as a marked overlay (shared pin, the [ADR-0136](0136-planning-skills-publish-through-a-work-store-seam.md) pattern) inside the Task-planning-skills component, manual-only. The name is kept upstream-verbatim to credit the flow's origin, deviating from the house rename precedent (to-tickets→to-tasks).

**A second upstream-verbatim name, for the opposite reason:** the interview primitive was later renamed `batch-grill-me`→`grilling` to match upstream. That is not origin-credit — it is the rename precedent applied to a fork whose local name had gone stale, because the upstream experiment it was named after (`in-progress/batch-grill-me`) was absorbed into shipped `productivity/grilling` and deleted. Where a local name still points at a live upstream skill, keep the house rename; where it points at nothing, take upstream's name.

Overlay deltas: pop is offered as a Work-store choice, and choosing it writes no repo doc by default — an absent doc means "defer to each machine's seeded `work-store.md`", while a committed doc pins the choice for the team; the triage-labels section is negated (pop ships no triage skill); no `.pop/` scaffolding ([ADR-0137](0137-the-pop-directory-is-the-in-tree-home-and-pop-toml-becomes-pop-config-toml.md) files stay lazily created). The `docs/agents/domain.md` write and the Agent-skills block are kept: they are how repo-resident agents discover these files at all. `pop doctor` stays untouched — the skill's own exploration phase is the "is this repo prepared" check.
