# A convention resolves to one answer plus the overlay

[ADR-0211](0211-a-repo-convention-resolves-through-a-composed-four-layer-stack.md) made a Convention kind resolve through four layers that **compose**: `get` emits every layer that speaks, labelled with its origin, lowest rank first, states that later ranks win direct contradictions, and leaves the reconciliation to the reading agent. Winner-take-all was tried first and rejected, on the ground that a convention pop derived on Monday would outrank a `docs/agents/commits.md` a teammate committed on Tuesday, silently and forever.

That objection is about a **rank order**, not about composition, and it does not survive putting the human's documents above pop's. Composition, meanwhile, has a cost the original decision did not price: a layer that is merely *stale* is never displaced, only out-ranked on the points where it directly contradicts. Prose that coexists with a better answer keeps reaching the agent forever. For `code-review` that is not a corner case — pop's guess at a coding standard, filed on one machine where no colleague can read it, would go on shaping every review after the team wrote down what they actually wanted.

The decision, in five parts:

1. **A convention resolves to exactly one answer, plus the overlay.** In order: `~/.agents/docs/<kind>.md`, else the repository's `docs/agents/<kind>.md`, else Convention memory, else the kind's Convention recipe. `~/.agents/docs/<kind>.overlay.md` is appended whenever it exists. Nothing else composes.

2. **The human's own document outranks the team's.** This reverses ADR-0211's layer identity, which had the human's bottom layer holding "preferences a team may overrule". Pop is a personal tool running on one human's machine, resolving conventions for agents working on that human's behalf; when the two disagree about how work should be done here, the person sitting at the terminal is the one being served. The team's document remains the answer wherever that person has not written one, which is the ordinary case.

3. **The two human layers now differ by mechanism, not only by rank.** `~/.agents/docs/<kind>.md` *replaces* — it is a complete answer offered in place of anyone else's. `~/.agents/docs/<kind>.overlay.md` *appends* — constraints that ride along with whichever answer won. That is a sharper distinction than "same author at opposite ends of a composed stack" and it is what makes two files by one author worth keeping.

4. **Convention memory becomes the fallback, and stands down as soon as any document exists.** It is pop's stand-in for a written answer; a written answer makes it redundant by definition. No staleness detection, no per-kind exception, and nothing left for a human to reconcile in their head.

5. **The Convention recipe is the last rank rather than a miss path.** The stack therefore always answers, `ErrNoConvention` is deleted, and `pop conventions get` exits 0 in every case. The recipe keeps its banner — the last rank is a *method*, and the banner is what tells a consumer to work it rather than follow it. For `code-review` that rank is now a real default standard: the recipe carries a named smell baseline (from Matt Pocock's `code-review` skill, whose output this repository's author already reviews against) as a floor beneath the three derivation sources, so a repository that has written nothing still gets something honest to hold a changeset against instead of the recipe's former instruction to record the nothing. That recipe records its result to `docs/agents/code-review.md` only, never to Convention memory: a review standard is prose about a team's taste, and one filed where a single machine can read it is the wrong artifact no matter what shadows it.

## Considered options

- **Keep composition and drop the memory layer from `code-review` alone** — rejected. It fixes the kind where the defect was noticed and leaves the mechanism that produced it in place for the others, and a kind resolving over a different number of layers than its siblings is a special case every future reader of `stack.go` has to carry.
- **Composition, with memory suppressed only by the repository layer** — rejected, though it is the narrowest correct-sounding rule. It preserves the case where a broad personal preference and a narrow team document genuinely complement each other, at the price of keeping composition's reconciliation burden for every kind and leaving the human's rank below the team's.
- **A per-kind resolution mode** — `code-review` selects, `commits` and `issue-tracker` compose — rejected. Two kinds behaving differently is variation nobody sees until it bites.
- **A fifth, lowest layer holding pop's shipped defaults** — rejected. It is cleaner on provenance than putting a default in the recipe, and it makes `get` never miss, which is the exact trigger that prints the recipe: every repository would settle silently for the generic floor and the derivation path would become unreachable. Making the recipe itself the last rank gets the same always-answers property while keeping the banner that says an answer has not been derived yet.
- **Exit 1 when the recipe is the winner** — rejected. Nothing reads it: the in-process consumers (`codeReviewConvention`, the Config dashboard's `StackPreview`) never see an exit status, and the external ones are agents reading prose, for whom the `RECIPE <kind>` header and the banner are a stronger signal than a number whose meaning has to be documented. A non-zero exit from a command that printed exactly what it was designed to print reads as failure to every shell, CI job and agent harness that sees it.

## Consequences

- **Amends [ADR-0211](0211-a-repo-convention-resolves-through-a-composed-four-layer-stack.md) on two counts** — the composition rule and the human-below-team rank. What survives from it: the closed kind enum, the four paths, per-kind recipes, memory's provenance frontmatter, and the division of labour where pop resolves and labels while the agent judges.
- **A personal `~/.agents/docs/<kind>.md` now discards the team's committed document entirely**, not just where the two conflict. That is the sharp edge of decision 2 and the reason to keep such a file narrow, or to put it in the overlay instead, where it appends rather than replaces.
- **`overrideRule`, `overrideRuleLine` and the `LAYER n OF m` rendering go.** `StackProse` emits the winner and the overlay; `pop conventions get` and the Config dashboard's preview show the same thing, so the human-facing and agent-facing surfaces cannot describe a convention differently. A suppressed layer is not displayed — the answer in force is the question those surfaces exist to answer.
- **A convention can now be a Contested key.** CONTEXT.md's Config dashboard entry said a convention never is, "its layers compose, so a second one speaking is not a first one quietly losing". Under winner-take-all a second layer speaking is exactly that.
- **`pop conventions unset` reports a different thing.** ADR-0211 had it print the stack that remains in effect because removing a layer rarely silenced a kind; now removing the winner promotes the next rank, which is the fact worth printing.
- **Every kind's recipe is now load-bearing prose**, since it is what a fresh repository actually receives. The `commits` and `issue-tracker` recipes stay methods; only `code-review` ships an opinion, and it ships it as a floor that any of the three sources above it overrides.
- Glossary: **Repo convention**, **Convention stack**, **Convention memory**, **Convention recipe** and **Convention overlay** are redefined; **Convention defaults** is added.
