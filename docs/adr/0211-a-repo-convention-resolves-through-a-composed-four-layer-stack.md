# A repo convention resolves through a composed four-layer stack

Pop keeps asking the same question in prose: how does this repository write its commits? Three skills answer it today with copy-pasted recipes that have already drifted — `to-tasks` reads `docs/commit-format.md` and discards pop-generated commits before sampling the log, while `grill-with-docs` and `grill-consolidate` sample five commits and do neither, so on a pop-drained repository they learn pop's own `tasks(...)` accent back from history. The answer is also re-derived from scratch by every agent, on every set, forever, and a human who corrects it has nowhere to put the correction.

The decision: a repository's conventions become a first-class thing pop stores and resolves, under a new top-level noun — `pop repo conventions get [KIND]`, `set <kind>` (body on stdin), `unset <kind>`, `recipe <kind>`. A **Convention kind** is a closed enum (`commits` and `issue-tracker` now, built for `code-review` and `verification`), because each kind's derivation is kind-specific work pop must know how to do. A kind resolves through a **Convention stack** of four layers, lowest rank first: `~/.agents/docs/<kind>.md`, the pop-written **Convention memory**, the repository's `docs/agents/<kind>.md`, and `~/.agents/docs/<kind>.overlay.md`. *(Rank order superseded by [ADR-0223](0223-a-convention-resolves-to-one-answer-plus-the-overlay.md): the answer is the first of `~/.agents/docs/<kind>.md`, the repository's document and Convention memory that holds something, and the overlay is appended to it. The four paths are unchanged.)*

The stack **composes**. *(Superseded by [ADR-0223](0223-a-convention-resolves-to-one-answer-plus-the-overlay.md): a kind resolves to exactly one answer plus the overlay, the override rule and the `LAYER n OF m` rendering are gone, and a rank the answer stood down is not shown at all. What survives below — pop orders and labels while the agent judges, and pop never merges prose — is unchanged.)* `get` emits every layer that exists, labelled with its origin, in rank order, and states the override rule; the agent reconciles them. Pop orders and labels — it never merges prose, because concatenating labelled sections is mechanical and testable while merging Markdown is not. This is the same division of labour the family exists for: the error-prone mechanical parts (which paths, worktree-to-repository resolution, filtering pop's own commits) move into the binary where they are testable, and the agent contributes only judgement. Rank therefore decides only direct contradictions, which is what makes the layer identities clean — the human's bottom layer holds preferences a team may overrule, the repository's document holds the team's rules, and the top **Convention overlay** holds the human's constraints that must survive any repository. Two layers by the same author at opposite ends of the stack is deliberate, and mirrors the config merge order, where `config.override.toml` outranks a hand-authored `config.toml` (ADR-0202). It is named *overlay* rather than override because pop already spends "override" on the Repo override and its runtime layer.

A miss is a **Convention recipe**, not an error message. `get` exits 1 with the kind's recipe on output and the agent decides what to do; the recipe is also reachable directly, since an agent improving an existing convention needs it too. *(Superseded by [ADR-0223](0223-a-convention-resolves-to-one-answer-plus-the-overlay.md) decision 5: there is no miss. The recipe is the last rank of the stack, so a kind nobody has answered resolves to it under its banner and `get` exits 0 in every case. The recipe stays reachable directly.)* Recipes are distinct in kind from conventions — the stack returns an answer, the recipe returns the method — and keeping them apart means no caller has to branch on which it received. The `commits` recipe carries the derivation that was skill prose until now, guard included, plus where to write the result: a convention derived from history goes to Convention memory, while one a human states in session prompts the agent to offer `docs/agents/commits.md`, because a fact the team should own belongs in version control. `get` also emits a ready-made one-line provenance summary for the agent to surface, so the "which source am I using" disclosure cannot drift across skills the way the recipe itself did.

## Considered options

- **A repo-scoped config key.** `pop config repo set` is documented as the only way pop writes a repo-scoped setting, and adding a key there is a two-line change. Rejected: that layer holds TOML scalars with keys reflected off `RepoRuntimeConfig`, and a convention is a multi-paragraph Markdown document a human may want to read, diff and hand-edit. Storing it as a file per kind under the repository's Task storage directory — already keyed by Repository identity, already holding `tasks/` and `maps/` — is the honest representation. The cost accepted: two repo-scoped surfaces, distinguished by *scalar setting* versus *prose document*.
- **Splitting `commits` into commit-format and commit-message.** Tempting because they have different consumers at different times: the Planned commit subject needs only the grammar, resolved at plan time, while the body is the agent's summary written at commit time. Rejected: split kinds when they have different *sources*, and here one document and one `git log` sample produce both. A repository that wants them separated writes two headings.
- **Winner-take-all precedence.** The first shape tried, and it forces an unpleasant question — a convention pop derived on Monday outranking a `docs/agents/commits.md` a teammate commits on Tuesday, silently, forever. Composition dissolves it: the repository's document is always read and always outranks Convention memory, so no staleness detection is needed.

## Consequences

- **[ADR-0207](0207-commit-conventions-resolve-at-plan-time-into-planned-subjects.md) is superseded.** Its core survives — the convention resolves once per Task set at plan time, renders into Planned commit subjects, and the executor commits them verbatim — but its *resolution rule* is entirely replaced. `docs/commit-format.md` is dropped in favour of `docs/agents/commits.md`, with no legacy alias.
- **The skills stop describing the recipe and start calling the command.** `to-tasks`, `grill-with-docs` and `grill-consolidate` all resolve through `pop repo conventions get commits`, which deletes the triplicated prose and its divergence. `integrate/to_tasks_commit_convention_test.go` is rewritten to assert the skill invokes the command, moving the assertions from pinning prose to pinning behaviour.
- **The Task set manifest still snapshots the resolved text verbatim.** Precedence governs resolution; the manifest records the result. A Remediation task born mid-drain renders from the manifest, so a human's mid-drain correction cannot rewrite a running set's grammar.
- **The recipes live in a new domain package that owns the enum, the stack resolution and the embedded recipe text**, per ADR-0208. `integrate/` is the installer seam and owns shipped assets; recipes are printed on demand, not installed.
- **The `issue-tracker` symlink migration is deliberately deferred.** `~/.agents/docs/issue-tracker.md` keeps being created by Integration refresh, so that kind's stack is never empty on an integrated machine and its recipe rarely fires. Shipping the kind anyway is still worth it: the tracker's existing two-layer resolution becomes the bottom two layers of a four-layer stack, gaining a per-repository memory and an overlay with no migration. The recipe is written now so it is already in place when the symlink is dealt with — and it is what fires on a machine where integration was never refreshed.
- `unset` reports the stack that remains in effect afterwards. Under composition, removing a layer rarely means the kind has gone silent, and saying so on the spot is cheaper than a help-text caveat.
