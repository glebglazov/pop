# Match the commit grammar this repository already uses

Nobody has written this repository's commit convention down, so this is pop's
own answer: read the recent log and write your commit to match it. It is
generic by construction — pop cannot know this project's taste — and any
document written at a rank above this one displaces it whole.

**One sample, both halves.** The `commits` convention covers **both** the
subject grammar — the type set, the scope vocabulary, mood, capitalisation and
length — **and** the body style: whether there is a body at all, what it is
expected to explain, and how it is wrapped. One log sample answers both. A
reading that pins the subject and says nothing about bodies is half a reading.

## Sample the last five commits

Read the last five commits — subjects and bodies — as a set, and take what they
share rather than what any one of them does. What they share is the convention;
match it.

**Discard pop-generated commits before sampling.** Pop's own default subjects
(`tasks(...)`) and pop's skill-commit shapes are pop's accent, not the team's.
Drop them and read the non-pop commits that remain. **Walk further back when the
recent window is all pop's**: take the next five, and keep walking until you hold
five non-pop commits or the history runs out. Without this guard pop learns its
own accent back from the log on every repository it has drained, and the
convention degenerates into a copy of itself.

## No discernible convention is a real result

A log whose non-pop commits share no type set, no scope vocabulary and no
consistent subject or body shape has answered the question: there is no grammar
here to match. Write the commit in pop's default format and say so if you are
asked what resolved. It is a result, not a failed reading, and it is not licence
to sample further back than the rule above allows or to invent a grammar the
repository never used.
