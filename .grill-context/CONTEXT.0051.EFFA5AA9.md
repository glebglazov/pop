+ Assist pane slot
  The digit 1–9 that names one **Assist pane** among the several a container may hold, carried on the pane itself beside the container id its `@pop_assist` tag holds. A new pane takes the lowest free slot, so a slot addresses the same session for as long as that pane lives and a closed pane leaves its digit unlisted rather than renumbering its siblings. Nine is the whole range: with every slot taken, asking for another is refused rather than opening a pane no digit can reach.

+ Assist pane menu
  The **Work dashboard** submenu that both assist verbs open instead of launching: one line per live **Assist pane** on its **Assist pane slot** — green running, grey idle — plus `n` to open another and `esc` back. A digit jumps to that slot's pane, an idle one respawning the session in place under the same three-state law the row's activity cluster teaches; `n` spawns and hands off, since an assist session is a pane you asked for in order to go talk to it. It opens with no pane live too, showing only `n`: the keystrokes never change shape under tmux state a row cannot show.

~ Assist session
  A human-in-the-loop session opened on an arbitrary **Task set** at its current derived status, without draining or re-running the **Verifier**. It presents the gate menu that status calls for — the **HITL gate prompt** for a **Human-blocked** or **Awaiting-approval Task set**, the **Verify-fail gate prompt** for a **Verify-failed Task set**, the **Failed gate prompt** for a failed one, and a generic assistance menu otherwise, which offers **Fold** as well when the set is Done and still bound. That fold runs in this process, injected as a seam by the CLI layer, so a refusal prints its reason in the menu — re-exec'ing `pop tasks fold` reduced every refusal to an exit status. Entered from `pop tasks assist <set>` inline in the current terminal, or from the **Work dashboard**, which spawns `<task-set>-assist` panes in the **Work window** — up to nine per set, each on its own **Assist pane slot** and reached through the **Assist pane menu**, never twinned blindly. The session itself reads **Task storage** and claims nothing, so it opens on any set that exists: one whose **Drain** is live, one parked at a gate, an **Archived Task set**, and one whose **Task manifest** will not parse — a broken manifest is exactly what a human opens Assist to look at, so the session names the parse errors and opens the menu on them. It addresses the set's own checkout under **Binding-first runtime resolution** rather than validating where the human was standing, so a sibling checkout of another repository stops mattering. Exclusivity lives on the verbs inside the menu: **Accept**ing a verdict, **Remediate** and **Fold** are **Tree-stable operation**s, so each takes the **Checkout claim** when it is chosen, takes an **Admission wait** on it when someone holds it, and gives it back when it is done — an interrupt during that wait returns to the menu rather than ending the session. Two sessions on one set are therefore safe rather than merely tolerated: neither holds the tree, and the verb each picks queues behind the other's. Agent assistance resolves its agent at the moment it is chosen, so a session opens and shows everything with every attended agent on cooldown, and the walk's refusal prints in the menu. The **Runtime shell** stays unlocked, and its banner says the checkout is not claimed for its duration. Being a human session it requires a TTY and refuses headless rather than degrading; the only other refusals left are the two that cannot work at all — a set that does not exist or is **Missing** (registered but not on disk), and no resolvable checkout.

~ Map assist
  `pop map assist [<map-id>]` — an attended agent session scoped to a whole Map rather than to one ticket, for the idea that arrives with no ticket in hand: new scope for an existing ticket, a fresh ticket, a patch of fog, or the realisation that something sits past the destination. Claims nothing and **resolves nothing** — `pop map resolve` belongs to the ticket's own claimed session, which is what keeps one non-research ticket per session traceable. Writes tickets, a ticket's `## Question`, `blocked_by` edges, `map.md` outside the `pop:generated` markers, and `pop map out-of-scope` — that last a scoping act, not a resolve. Runs in up to nine panes per Map in the **Map session**'s `map` window, each tagged `@pop_assist` with the Map id and holding its own **Assist pane slot**, so `pop map assist` lands in the lowest live slot and the **Assist pane menu** is what opens another; it closes by re-running `pop map register` to work the MALFORMED loop. Concurrent sessions no longer serialise the prose they write: `map.md` outside the markers is last-writer-wins between two assist panes, which is the price of the second conversation.
