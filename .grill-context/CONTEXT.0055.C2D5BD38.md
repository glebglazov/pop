+ Phase session choice
  The whole Agent entry a human selects for Refine or Verify during one interactive run. It takes precedence over that phase's launch flags and defaults, restricts the phase to that entry, and changes no other role or saved state.
  under: Task execution

~ Assist session
  A human-in-the-loop session on a Task set at its current derived status. It offers status-appropriate assistance and completion actions, plus explicit Refine and Verify actions where their manual command rules permit them; opening the session runs no phase and drains no work. Agent and phase choices last for that session only, and a phase result never completes an open HITL task on its own. Existing runtime resolution, checkout claims, gate actions and diagnostics retain their documented rules.
  was: A human-in-the-loop session opened on an arbitrary **Task set** at its current derived status, without draining or re-running the **Verifier**. It presents the gate menu that status calls for — the **HITL gate prompt** for a **Human-blocked** or **Awaiting-approval Task set**, the **Verify-fail gate prompt** for a **Verify-failed Task set**, the **Failed gate prompt** for a failed one, and a generic assistance menu otherwise, which offers **Fold** as well when the set is Done and still bound. That fold runs in this process, injected as a seam by the CLI layer, so a refusal prints its reason in the menu — re-exec'ing `pop tasks fold` reduced every refusal to an exit status. Entered from `pop tasks assist <set>` inline in the current terminal, or from the **Work dashboard**, which spawns `<task-set>-assist` panes in the **Work window** — up to nine per set, each on its own **Assist pane slot** and reached through the **Assist pane menu**, never twinned blindly. The session itself reads **Task storage** and claims nothing, so it opens on any set that exists: one whose **Drain** is live, one parked at a gate, an **Archived Task set**, and one whose **Task manifest** will not parse — a broken manifest is exactly what a human opens Assist to look at, so the session names the parse errors and opens the menu on them. It addresses the set's own checkout under **Binding-first runtime resolution** rather than validating where the human was standing, so a sibling checkout of another repository stops mattering. Exclusivity lives on the verbs inside the menu: **Accept**ing a verdict, **Remediate** and **Fold** are **Tree-stable operation**s, so each takes the **Checkout claim** when it is chosen, takes an **Admission wait** on it when someone holds it, and gives it back when it is done — an interrupt during that wait returns to the menu rather than ending the session. Two sessions on one set are therefore safe rather than merely tolerated: neither holds the tree, and the verb each picks queues behind the other's. Agent assistance resolves its agent at the moment it is chosen, so a session opens and shows everything with every attended agent on cooldown, and the walk's refusal prints in the menu. The **Runtime shell** stays unlocked, and its banner says the checkout is not claimed for its duration. Being a human session it requires a TTY and refuses headless rather than degrading; the only other refusals left are the two that cannot work at all — a set that does not exist or is **Missing** (registered but not on disk), and no resolvable checkout.
