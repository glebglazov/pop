+ Prior-art check
  The obligation pop's own implement frame puts on a builder before it writes mechanism —
  a busy flag, a `try`/`catch` that turns an error into a message, a success notice, a
  confirmation, a retry — to first find the composed form the repository already has, and
  to name in its summary what it matched or state that no prior art existed. Trigger-led
  rather than location-led: hand-written plumbing is the signal, and the search then walks
  the task's **Orientation** files, the directory the change lands in, and the repository,
  stopping at the first hit. It is pop's, not the **Implementation convention**'s, so no
  written rank can displace it and it rides every implement prompt whatever
  **Implementation convention inlining** is set to; the **Refiner** carries its inverse,
  since "unfamiliar is not a finding" protects existing idiom without making a failure to
  adopt one nameable, and an unnamed rule is an unfixable one.

+ Refine mark
  Whether a terminal **Task set**'s changeset was held to the standard at all, carried
  beside its status the way a **Verification mark** is: refined, or not — with the reason
  (interrupted, gate-blocked, abandoned, never ran) as detail beside the mark rather than a
  value inside it, since all four mean one thing to a reader signing off. It exists because
  a **Refine episode** records only a refined outcome, so a pass that died leaves the
  episode armed and no surface says the check never happened. Derived with no new column —
  a Captured run of phase `refine` exists or does not, and its outcome says which — and
  resolved once beside **Verified status resolution** rather than re-derived per surface.
  It gates nothing: parking a **Drain** on an agent hiccup would trade one failure for a
  worse one. Gate-blocked is the reason worth surfacing in words, being a fact about the
  changeset rather than about the pass — the scoped gate was already red when refinement
  began.
  avoid: refine status, refine flag, unrefined badge
