## Left in this changeset

1. **`tasks/verify.go:1034` and `:1058`: `verifyReport.AuthorField` ("Verifier") is never rendered.** Both Verify report writers pass `""` as the agent, so a Verify report never records which agent judged. A Refine report does record its agent. To fix this, `runConfiguredVerifier` would have to return the agent it settled on, and `runAndStoreVerdict` would pass that agent through. That is a change to behaviour and to the shape of what is stored, so it is report-only.
2. **`tasks/verify.go:1007`: the comment says more than the code guarantees.** It says that filing the report inside the transaction means a failed Accept leaves no report. That is true when a quiescence refusal happens or when `PutVerifyVerdictExec` fails. But the report is a plain file write: if the transaction fails to commit after that write, the report stays on disk. There are two possible fixes. One is to narrow the comment to "a refused Accept or a failed verdict write". The other is to write the report after the commit, and accept the opposite risk. Choosing between them is a decision about behaviour, so I left it.
3. **The `refactor` commit (46a5db97) edits test files** (`refine_test.go`, `refine_surfaces_test.go`, `prompt_golden_test.go`, `refiner_envelope_test.go`, `remediation_history_test.go`, `agent_read_only_posture_test.go`). This breaks "a refactor changes no test file". The edits only follow renamed unexported symbols (`renderRefineDocument` → `refineReport.render`, `RefinePointer` → `ReportPointer`, and similar). That is because those tests call the internals directly. The tests themselves were coupled that way before this changeset; see below.
