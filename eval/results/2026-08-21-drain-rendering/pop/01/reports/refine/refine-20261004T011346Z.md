## Left in this changeset

1. **`tasks/attempts.go:448–449` with `tasks/run_selected_task.go:100`: an exhausted walk prints two red ending lines for one task.** `disposeExhaustedWalk` still prints `✗ Out of agents for demo/01-a after 4 attempts`. Then `runSelectedTask` prints `✗ demo/01-a out of agents (left open)`. The commit says every task ending gets one result line. In this case it gets two, and the attempt breakdown comes *before* the result line, but on the done path it comes *after*. A better design: `disposeExhaustedWalk` keeps only its detail lines (`Last:`, the provider/turn-cap advice), and the Task result line becomes the one headline. This is a change to visible behaviour, so this pass only reports it.
2. **`tasks/executor.go:291`: the single-task `RunTaskWith` prints a result line only on success.** In a single-task run, an exec error, a human-healing stop and a time-healing quota pause print no Task result line. The drain path prints one for each of these endings. If the Task result line is only for drains, the single-task done line is the exception. If it is for every task ending, the other three single-task endings are missing. The design should pick one rule. This is behaviour, so it is report-only.
3. **`tasks/drain_header.go:12–14`: `DrainHeader.BindingKind` is a string for a closed domain concept.** It can only be `"managed"`, `"adopted"` or empty, and `implement.drainHeader` sets those values from `Binding.Provisioned`. The standard says a primitive that stands in for a domain concept should have its own small type, for example a typed constant set or a `Provisioned`/`Bound` pair that `Print` renders. This is an exported field, so it is report-only.
